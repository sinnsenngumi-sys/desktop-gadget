## 1. 概要と前提

Windowsのデスクトップに、すりガラス風のカード3枚（時計・日付、天気、使用量）を常駐表示する個人用ガジェットを作る。

- **見た目**: 「見え方1」。半透明でぼかしの入った角丸パネルが、壁紙の上に並ぶ。
- **表示内容**: 時計（アナログ／デジタル切替、秒まで）、日付、天気（気温・湿度・雨雲レーダー）、CPU／GPU／RAM使用量。
- **対象OS（仮置き）**: Windows 11。Windows 10も動かすが、ぼかしの見た目は保証しない。
- **利用範囲（仮置き）**: 個人利用。配布や販売をする場合は、天気・レーダーのデータ規約の見直しが必要になる。
- **範囲外（仮置き）**: ドック、メール、カレンダー、音楽。必要になれば後から足す。
- **進め方**: コードはこちらで書く。Windows実機での動作確認はあなたに依頼する。

* **動作環境（確認済み）**: Windows 11 25H2のノートPC。GPUはIntel Iris Xe Graphics（内蔵）とGeForce GTX 1650 Ti（外付け）の2枚。モニターはふだんノートの画面だけで、まれに外付けを1枚つなぐ。

## 2. 画面構成

幅440pxのカード3枚を縦に並べ、カード間は16px、角丸は28pxにする。設置位置はデスクトップ左上（仮置き）で、ドラッグと設定で移動できる。

| カード | 大きさ（幅×高さ、px） | 中身 |
| --- | --- | --- |
| 時計・日付 | 440×240 | 時計（デジタルまたはアナログ）、日付 |
| 天気 | 440×200（レーダー非表示）／440×460（レーダー表示） | 気温、湿度、天気アイコン、雨雲レーダー |
| 使用量 | 440×200 | CPU、GPU、RAMの3行 |

- **拡大縮小**: 全体と、カードごとの倍率を設定で変えられる（50〜150%、既定100%）。レーダーの高さも別に変えられる（120〜260px）。窓の大きさは、カードの合計に合わせて自動で変わり、スクロールを出さない。
- **カード単位の表示切替**: どのカードも設定でオン・オフできる。
- **カードごとに別ウィンドウにするかどうか**: ぼかしの方式に関わるため、§8で決める。

* **並べ方**: 「自動／縦1列／横2列」を選べる（既定は自動）。自動は、カードの合計の高さが画面に収まらないときに横2列（左に時計と使用量、右に天気）へ変え、それでも足りないときは、画面に収まるまで縮小する（最小50%）。設定を開いている間は縮小しない。

## 3. 時計と日付

時計はデジタルとアナログを切り替えられ、どちらも秒まで表示する。

| 項目 | 仕様 | 既定値 |
| --- | --- | --- |
| 表示モード | デジタル／アナログ。設定画面とトレイメニューで切り替え | デジタル |
| 秒 | デジタルはHH:MM:SS、アナログは秒針。設定でオフにもできる | オン |
| 時刻形式 | 24時間／12時間 | 24時間 |
| 更新 | 毎秒。秒の切り替わりに合わせる。端末の時計とタイムゾーンに従う | — |
| アナログの文字盤 | 目盛りだけの簡素なデザイン。秒針は滑らか／1秒刻みを選べる | 1秒刻み |
| 日付 | 「2026年11月2日（月）」形式。年・曜日の表示有無を選べる | 年月日＋曜日 |
| 文字色 | 壁紙の明るさに合わせ、白／黒を選べる | 白 |

## 4. 天気

気温と湿度を必須で表示し、雨雲レーダーは同じカードに重ねて見る。レーダーは気象庁のタイルを第一候補にする。

### 表示項目

| 項目 | 仕様 | 優先度 |
| --- | --- | --- |
| 気温 | 現在の気温（℃。華氏は設定で選べる） | 必須 |
| 湿度 | 現在の相対湿度（%） | 必須 |
| 場所 | 地名を表示。設定で地名検索または緯度経度を指定 | 必須 |
| 天気 | アイコンと短い文言（晴れ、雨など） | 推奨 |
| 更新時刻 | 最後に取得した時刻。取得失敗時は「古いデータ」と明示 | 推奨 |
| 雨雲レーダー | 地図に雨雲を重ね、過去から現在をアニメで見る。設定でオン・オフ | 希望 |
| 警報・注意報 | 湿度の下に、発表中の警報・注意報を表示。特別警報、警報、注意報の順に並べ、2件まで名前つきで示し、残りは「ほか○件」とする。ないときは「警報・注意報なし」 | 希望 |

### 気温・湿度のデータ元（候補）

Open-Meteoを第一候補にする。気温・相対湿度・天気コードを現在値として取れ、APIキーは不要。無料枠は非商用限定で、1日1万回未満が目安、データはCC BY 4.0（出典表記が必要）。この記載は第三者の解説によるもので、公式規約ページは開けなかったため、実装前に確認する。取得間隔は10分（仮置き）。

### 雨雲レーダーのデータ元（候補）

| 候補 | 範囲と精度 | 制約 | 評価 |
| --- | --- | --- | --- |
| [気象庁 高解像度降水ナウキャスト](https://www.jma.go.jp/jma/kishou/know/kurashi/highres_nowcast.html) | 日本。陸上と沿岸は250m、30分先まで予測、以降60分先までは1km | 公式に案内されたAPIではなく、仕様が予告なく変わる可能性がある。出典表記が必要 | 第一候補。個人利用なら無料で使える見込み（下の調査結果を参照） |
| [RainViewer無料API](https://www.rainviewer.com/api/transition-faq.html) | 世界。過去2時間、10分間隔。ズーム7まで（約1km/画素） | 2026年1月1日以降、ズーム7まで、1IP毎分100回、予測データは終了。個人・教育用のみ | 町単位の細かさは出ない。気象庁が使えない場合の予備 |
| LibreWXR（自分でサーバーを立てる） | RainViewer互換。日本は気象庁由来の合成雨量 | セルフホストの運用が必要 | 手間が大きいため不採用寄り |

無料のデータはどれも制約がある。気象庁タイルを第一候補にし、RainViewerは予備にする。詳しくは下の調査結果を参照。

### 気象庁データを個人で使えるか（調査結果）

個人利用で無料で使える見込みが高い。ただし公式に案内されたAPIではないため、仕様変更に備える。

- **取得できるもの**: 気象庁の「雨雲の動き」ページが使う画像タイル。時刻一覧のJSON（実況は`targetTimes_N1`、予測は`targetTimes_N2`）と、時刻を指定して取るタイルPNG。認証や登録は不要という検証例がある。
- **時刻とコマ数**: 5分刻み。実況は37コマ、予測は12コマ（60分先まで）を返したという実測（2026年9月20日）がある。
- **タイルのURLの形**: `https://www.jma.go.jp/bosai/jmatile/data/nowc/{基準時刻}/none/{有効時刻}/surf/hrpns/{z}/{x}/{y}.png`。
- **ズーム**: 2024年12月に、偶数のズームレベルだけ提供されるようになったという報告がある。アプリでは4・6・8・10を使う。
- **公式の位置づけ**: Home Assistant連携の記録に「公式に案内されたAPIではない」とある。予告なく変わる可能性があり、ズームの件がその例。
- **利用規約**: 気象庁ホームページのコンテンツは公共データ利用規約に準拠して利用でき、「出典：気象庁ホームページ」とURLの表記が要る。加工した場合は、加工した旨の明記も要る。「ナウキャスト」のページはe-Govでは政府標準利用規約（第2.0版）と記載されている。自動取得に関する記述は、開いた規約ページにはなかった。
- **負荷への配慮**: 2021年8月にアクセス集中で気象庁ホームページが見にくくなった。取得は5分より短くしない。表示範囲のタイルだけを取り、取得済みのタイルはキャッシュする。
- **取得の場所**: 時刻一覧のJSONにCORSヘッダーがなく、ブラウザから直接取れなかった報告がある。取得はアプリ側（Rust）で行い、画像だけ画面に渡す。
- **有償の公式配信**: GRIB2形式のデータは、気象業務支援センター経由の配信資料で、1ファイル最大約80MB。個人の常駐ガジェットには不向きで、契約条件は確認できていない。
- **背景地図**: 国土地理院タイルを使い、「地理院タイル」の出典を表示する。気象庁の表示例でもこの地図が使われている。

採用方針: 気象庁タイルを第一候補にする。取得に失敗したときはレーダー部分に「取得できません」を示し、気温・湿度は続けて表示する。RainViewerは予備に回す。タイルの取得先は設定ファイルに切り出し、変更に対応しやすくする。

### 警報・注意報のデータ元（調査結果）

気象庁ホームページが使うJSONで、市区町村単位の発表状況を取れる見込み。レーダーと同じく、公式に案内されたAPIではない。

- **取得先**: `https://www.jma.go.jp/bosai/warning/data/r8/{府県予報区のコード}.json`。2026年5月29日以降の新しい体系（令和8年体系）の形式。旧形式は`.../warning/data/warning/{コード}.json`で、5月28日以前の体系。
- **地域コード**: `https://www.jma.go.jp/bosai/common/const/area.json`の対応表を使う。例として、東京都は130000。市区町村は7桁のコード。
- **市区町村の単位**: 市区町村ごとのJSONはなく、都道府県のJSONの中に市区町村ごとの発表が入っている。
- **読み方**: `areas`の各要素が市区町村コードを持ち、`warnings`に警報コードと状態が入る。状態が「解除」「発表警報・注意報はなし」のものは除く。
- **体系の変更への備え**: 2026年5月29日から警報コードの対応表が新しい体系に切り替わった（旧と新で別表）。コード表は気象庁の解説資料の別表に従い、アプリに持つ。未知のコードは「その他の警報・注意報」と表示する。
- **規約と負荷**: レーダーと同じ気象庁ホームページの規約（出典表記）に従う。10分間隔で取得し、バッテリー時は20分、ゲーム中は停止する。
- **公式の別ルート**: 気象庁防災情報XMLに、警報・注意報の電文がある。過去に試行配信が行われた記載があるが、現在の受信条件は未確認。
- **表示の決め方**: 特別警報（紫）、警報（赤）、注意報（黄）。色だけに頼らず、「大雨警報」などの名前を併記する。
- **通知**: 新しい警報が出たときのWindows通知は、今回は範囲外。必要なら後から足す。
- **注意**: この表示は、避難などの判断の唯一の根拠にしない。アプリの表示が遅れる・止まる可能性があるため、気象庁の公式発表を確認する。

### レーダー表示の仕様

- 地図の上に雨雲を重ね、現在地マーカーを中心に置く。
- 過去2時間をアニメ再生する（予測が取れるデータ元なら、予測分も続けて再生）。
- 5〜10分ごとに更新。オフライン時は最後の画像を残し、「古いデータ」を示す。
- 地図の下絵（ベースマップ）も利用規約と出典表記を確認して選ぶ（国土地理院タイルなど、候補は要調査）。

* **地図の色**: ライトとダークを設定で切り替える（既定はダーク）。どちらの地図でも雨雲が見えるよう、雨雲の色をそれぞれ調整する。
* **現在地の表示**: 地図の中心に白い輪を置く。暗い縁を付けて、明るい地図でも見えるようにする。
* **凡例**: 地図の下に「弱 → 強」の色帯を表示する（試作のまま）。
* **雨雲の粒**: 粒が細かすぎると見にくいため、まとまりで見える大きさにそろえる。試作では1粒を6px、まとまりを約20pxにしている。実際のタイル画像では、地図の拡大率と表示サイズで調整する。

## 5. CPU・GPU・RAM使用量

左に項目名と数値、右に横棒グラフを置き、項目ごとに色を変える。色は設定で自由に変えられる。

| 項目 | 左側の表示 | 右側の横棒 | 既定色 | 取得方法（候補） |
| --- | --- | --- | --- | --- |
| CPU | 「CPU 38%」 | 0〜100%の使用率 | シアン #6FD0FF | OSの使用率（全コア平均） |
| GPU | 「GPU 21%」 | 0〜100%の使用率 | 紫 #C9A8FF | Windowsの性能カウンター「GPU Engine」 |
| RAM | 「RAM 61%」 | 使用中・搭載量の割合 | 緑 #9AE6B4 | OSのメモリ使用量 |

- **色設定**: 項目ごとにカラーピッカーとHEX入力で変更。「既定に戻す」を用意する。色だけに頼らず、項目名と数値を必ず併記する。
- **棒の背景**: 白の約20%の半透明。棒の左端は角丸。
- **更新間隔**: 1秒（既定）。1〜5秒で変更できる。
- **RAMの追加表示**: 設定で「9.8 / 16 GB」の併記を選べる。
- **GPUの扱い**: Task Managerと同じ考え方で、最も忙しい処理エンジンの値を使用率とする。このカウンターはAMD・Intel・NVIDIAで共通に使える。NVIDIAは専用のライブラリで、より詳しく取れる。
- **GPUが複数ある場合**: 既定は使用率の高い方を表示し、名前を小さく併記する（例: Iris Xe／GTX 1650 Ti）。設定で片方に固定もできる。この環境の2枚は、Windowsの性能カウンターで同じ方式で取れる見込み。
- **取得できない場合**: GPUがない、または取れないときは「—」を表示し、棒は空にする。起動直後の最初の1回は値が出ない性質があるため、1〜2秒待つ。

### 文字の色（項目ごと）

項目ごとに文字の色を変えられる。変えていない項目は、「外観」の文字色（白／黒）に従う。

| 項目 | 対象の文字 |
| --- | --- |
| 時計（時刻） | デジタルの時刻、アナログの文字盤と針、アナログ横の時刻（秒針はオレンジのまま） |
| 日付 | 日付の文字 |
| 気温 | 気温の数字 |
| 湿度 | 「湿度」の文字と数字 |
| 場所・更新時刻・説明 | 地名と天気の文言、更新時刻、レーダーの説明・凡例の文字 |
| CPU／GPU／RAM | それぞれの項目名と数値（棒の色は別の設定） |

- 変えた色は、項目ごとに「戻す」で元（全体の文字色に従う状態）に戻せる。

- **設定の保存**: いまはアプリの内部（この端末の中）に保存し、下げた色やサイズを開き直しても戻らない。JSONファイルへの書き出し・読み込みは、フェーズ3で足す。

## 7. 動作条件（表示維持・ゲーム中・バッテリー）

デスクトップ表示でも消さず、ゲーム中は更新を止め、バッテリー駆動中は更新頻度を半分にする。

### 更新間隔（既定値）

| 対象 | 電源接続時 | バッテリー駆動中 | ゲーム中 |
| --- | --- | --- | --- |
| 時計・日付 | 1秒 | 1秒（仮置き） | 停止 |
| 天気（気温・湿度） | 10分 | 20分 | 停止 |
| 警報・注意報 | 10分 | 20分 | 停止 |
| 雨雲レーダー | 5分 | 10分 | 停止 |
| CPU・GPU・RAM | 1秒 | 2秒 | 停止 |

- 「半分」は更新の回数を半分にする意味で、間隔を2倍にする。
- 時計は秒表示のため、1秒のままにする（仮置き）。2秒間隔にすると秒が飛ぶ。
- ゲーム中が最優先で、バッテリー駆動の条件より先に適用する。
- ゲームを終えたら、全項目を即座に1回更新する。
- 画面ロック中とスクリーンセーバー中も、ゲーム中と同じく停止する。

### ゲーム中の判定

Windowsが返す「ユーザーの状態」を使う。全画面アプリ、Direct3Dの全画面（排他モード）、プレゼンテーションモード、ロックやスクリーンセーバーを区別して取得できる。枠なしの全画面表示（ボーダーレス）のゲームは拾えない場合があるため、手前のウィンドウがモニター全体を覆っているかの確認も併用する（Chromiumも同じ発想）。それでも拾えないゲームは、設定で実行ファイル名を追加して「ゲーム扱い」にする。

### デスクトップ表示（Win+D）でも消さない

- 最背面に置くだけの窓は、Win+Dで一緒に隠れる例がある。Rainmeterでも、位置を「Bottom」にしたスキンはWin+Dで隠れると案内されている。
- 自作では、窓をデスクトップの層（壁紙の上、アイコンの下）に取り付ける方式で残せる見込み。Tauri向けに、そのための既存プラグイン（tauri-plugin-desktop-underlay）がある。
- **代償**: この方式の窓は、マウスやキーボードの操作を受け付けない。時計の切替や設定は、トレイアイコンのメニューと設定画面から行う。
- 取り付け先の探し方に癖がある。デスクトップの構造が環境で異なるため、対象の窓を全ウィンドウから探す必要があるとの報告がある。Windows 11の実機で確認する。
- 取り付けた窓にOSのぼかし（アクリル）が効くかは未確認。この方式では擬似ガラスが有力になる（→§8）。

### 追加する設定項目

| 項目 | 選択肢 | 既定 |
| --- | --- | --- |
| ゲーム中の動作 | 全停止／何もしない | 全停止 |
| ゲーム扱いにするアプリ | 実行ファイル名を追加 | なし |
| バッテリー駆動中の間隔 | 既定の1〜4倍 | 2倍 |
| バッテリー駆動中も時計は1秒 | オン／オフ | オン |
| ロック中の停止 | オン／オフ | オン |

### ノートPCと外付けモニターの扱い

- 外付けモニターをつないでも、表示はノートの画面に残す（既定）。設定で外付けに切り替えられる。
- 画面構成の変更を検知し、外付けを外したときに窓が画面外に取り残されないよう位置を戻す。
- 拡大率の違う画面を行き来しても、大きさが崩れないよう再計算する。
- スリープからの復帰時に、全項目を即座に1回更新する。
- Windowsの「バッテリー節約」中の扱い（バッテリー駆動と同じにするか）は、実機で確認して決める。

## 8. 非機能要件と技術方針

実装はTauri（Rust＋WebView2）を推奨する。雨雲レーダーの地図表示と、アナログ時計などの自由な見た目を両立しやすいためで、Rainmeter単体では地図の表示が難しい。ThemiaもTauri設計で、10MB未満と紹介されている。

### 非機能要件

| 項目 | 目標（仮置き） |
| --- | --- |
| 負荷 | 通常時のCPU 1%未満、メモリ150MB以下。実測して見直す（参考: Themiaのレビューではウィジェッ、10個でCPU 0.1%・約70MB） |
| 起動 | ログイン後5秒以内に表示 |
| オフライン | 天気とレーダーは最後の値を残し、「古いデータ」を表示。時計と使用量は影響を受けない |
| プライバシー | 利用状況の送信なし。位置情報は端末内の設定ファイルだけに保存。外部通信は天気・レーダー・地図の取得先に限る |
| 安全 | 管理者権限は不要。通信先を許可リストで限り、アプリに与える権限も必要最小限にする |
| 表示 | 高DPIと複数モニターで崩れない。文字は地の色に対して読みやすいコントラストを保つ |
| 配布 | 個人利用は実行ファイルのみ。人に渡す場合はコード署名を検討 |

### すりガラスの作り方（候補）

Tauriで透明な窓を作るには、窓の設定で`transparent`をオンにし、ページの背景も透明にする。その上で、次の3方式を実機で見比べて決める。

| 方式 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| アクリル（OSの効果） | window-vibrancyの`apply_acrylic`で窓にすりガラスをかける | 本物の透過ぼかし | Windows 10 v1903以降とWindows 11 build 22000で、窓を動かすときに重いと注記されている。効果は窓全体にかかる |
| Mica | `apply_mica`。Windows 11のみ | 性能上の注記がない | 透け感は弱い（壁紙の色を薄く映す効果） |
| 擬似ガラス（私の推奨） | 壁紙をあらかじめぼかした画像を、各カードの背景に敷く | 軽い。カードの形に合わせられる | 壁紙を変えたときに再生成が必要。壁紙以外は映らない |

デスクトップのウィジェットでは背後にあるのが壁紙だけなので、擬似ガラスで見た目は十分に近づけられる見込み。アクリルの重さは現在のWindowsビルドで確認が必要。

**実機で見た結果（2026年11月2日、Windows 11 25H2）**

- **ドラッグの重さ**: どの方式でも感じなかった。
- **アクリル**: 窓全体が均一な灰色になり、カードの形とは分かれない。すりガラスらしさは弱い。
- **ブラー**: 窓全体が黒っぽくなる。
- **なし**: 完全に透けるが、デスクトップのアイコンが文字に重なり、読みにくい。
- **Mica**: 窓全体が均一な濃い灰色になり、壁紙の透けはほとんどない。文字は読みやすいが、すりガラスらしさはない。
- **見込み**: どの方式も窓全体にかかるため、カードの形にすりガラスをつけるには、壁紙をカードの形にぴったり合わせて、ぼかして敷く「擬似ガラス」が有力。

* **結論**: 3方式とも窓全体にかかり、カードの形のすりガラスにならない。擬似ガラスで進める。横2列への自動切替は、実機で動作を確認済み。

**擬似ガラスの仕様（採用）**

- **壁紙**: 静止画1枚（確認済み）。Windowsの設定（レジストリ）から、画像のパスと「ページ表示」の設定を読む。
- **表示方法**: 塗りつぶし・調整・拡大して表示・中央に対応。タイルとスパンは、近い見え方で代用する。
- **位置合わせ**: モニターの位置と窓の位置から、各カードの背景を計算して合わせる。窓を動かすと追従する（動かしている間は少し遅れることがある）。
- **調整**: ぼかしの強さとガラスの濃さは、既存の設定で変えられる。
- **壁紙を変えたとき**: アプリを開き直すと反映される。自動で検知するのは次の段階。
- **外付けモニター**: 読むのはメイン画面の壁紙と1枚だけ。外付け側に窓を移すと、ズレる場合がある。
- **失敗したとき**: 単色の半透明表示に切り替え、理由をメッセージで示す。
- **文字の読みやすさ**: 明るい壁紙では、設定で文字色を黒に切り替える。自動判定は後回し。

### 部品（想定）

- 画面: HTML、CSS、JavaScript。アナログ時計はSVG。
- CPU・RAM: OSの情報を読むRustの既存ライブラリを使う。
- GPU: Windowsの性能カウンター（PDH）を読む。NVIDIAは専用ライブラリも候補。
- 天気・レーダー: §4のデータ元。地図の描画には軽量な地図ライブラリを使う。

## 9. 他に検討すべき事項

置き場所とレーダーのデータ元は方針が決まった。残る最優先はぼかし方式で、残りは作りながら決めてよい。

| 事項 | 論点 | 私の推奨 |
| --- | --- | --- |
| 置き場所 | 決定済み: デスクトップ表示でも残す。取り付け方式は実機で確認する | デスクトップの層に取り付け、デスクトップ表示でも残す（§7） |
| ぼかし方式 | §8の3方式のどれを使うか | 擬似ガラスで試作し、アクリルと実機で見比べる |
| レーダーのデータ元 | 気象庁は公式案内のAPIではない点、RainViewerの制限（ズーム7、個人用のみ）、地図タイルの規約 | 気象庁タイルを第一候補、RainViewerを予備にする |
| 個人利用か配布か | 人に渡すと、天気とレーダーの無料枠の条件を満たさなくなる可能性 | 個人利用で進める |
| 位置情報 | 手入力か、Windowsの位置情報か | 手入力（プライバシーを優先） |
| 全画面アプリ・ゲーム中 | 重ね表示の負荷と、ゲームへの影響 | §7のとおり。全画面の検知とゲーム指定で全停止 |
| 省電力 | ノーPCのバッテリー時や画面ロック中の更新 | §7のとおり。バッテリー時は間隔を2倍、ロック中は停止 |
| GPUの取得 | 内蔵と外付けの両方がある場合。「使用率」の定義がTask Managerと一致するか | 設定で選択。定義はTask Managerに合わせる |
| 色の読みやすさ | 壁紙が明るいと白文字が読めない | 白と黒を切り替え。自動判定は後回し |
| 起動・更新・署名 | 自動起動、アプリの更新、SmartScreenの警告 | 自動起動は任意。署名は配布するときに検討 |
| 動作確認の環境 | Windows実機でのビルドと表示確認が必要 | あなたの環境で確認し、スクリーンショットを共有して調整 |
| 将来の拡張 | ドック、ディスク、ネット、温度、音楽 | カードを足せる構造にしておく |
