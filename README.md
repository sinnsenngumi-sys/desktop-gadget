# DesktopGadget（フェーズ3：使用量と動作状態の実測）

見え方1（すりガラスのカード）を、Tauriの透明な窓に載せたものです。擬似ガラスはフェーズ2で採用済みです。

フェーズ3では、次の2つを実測に置き換えました。

- **CPU・GPU・RAMの使用量**（仕様書§5）
  - CPU: Windowsの性能カウンター「% Processor Utility」（Task Managerと同じ値）
  - GPU: 性能カウンター「GPU Engine」。Task Managerと同じく、最も忙しい処理エンジンの値を使用率とする。名前はDXGIから取る
  - RAM: OSのメモリ使用量。設定で「9.8 / 15.7 GB」を併記できる
- **動作状態**（仕様書§7）: 電源（AC／バッテリー／バッテリー節約）、ゲーム中（全画面・Direct3D全画面・プレゼンテーション・枠なし全画面・指定アプリ）、ロック・スクリーンセーバー。状態に合わせて更新の間隔を変え、止める

天気・警報・レーダーはまだダミーです。

## 進め方（残りのフェーズ）

| フェーズ | 内容 | 状態 |
| --- | --- | --- |
| 1〜2 | HTML試作、Tauri雛形、擬似ガラス | 完了 |
| 3 | CPU・GPU・RAMの実測、動作状態の検知 | **今回** |
| 4 | 天気（Open-Meteo）、警報・注意報、雨雲レーダー（気象庁タイル） | 次 |
| 5 | 常駐化: デスクトップの層への取り付け（Win+Dでも残す）、トレイアイコン、別窓の設定画面、JSONの書き出し・読み込み、自動起動、モニター構成の変化への追従 | その次 |

Win+Dでも残す処理は、当初フェーズ3の予定でしたが、フェーズ5に移しました。デスクトップの層に取り付けた窓はマウス操作を受け付けなくなるため、トレイアイコンと別窓の設定画面と同時に入れないと、いまの「設定」ボタンが使えなくなるためです。

## 準備（初回のみ）

1. **Microsoft C++ Build Tools** を入れる（インストーラーで「C++ によるデスクトップ開発」を選ぶ）
2. **Rust** を入れる（rustup。既定の MSVC 版でよい）
3. **Node.js**（LTS）を入れる
4. WebView2 は Windows 11 に標準で入っています

入れたあと、PowerShell を開き直してください。

## 起動

```powershell
cd desktop-gadget
npm install
npm run dev
```

初回はRustの部品を取得してビルドするため、数分かかります。

## 試すこと（フェーズ3）

起動して2秒ほど待つと、使用量の欄に実測の値が出ます（最初の1秒ほどは「—」）。

1. **CPU・RAM**: Task Manager（パフォーマンス タブ）と並べて、値がおおむね合うか
2. **GPU**: 何か重い処理（動画の再生、ゲーム、ブラウザのWebGLデモなど）をして、値が上がるか。既定では、GPUごとに1行ずつ並び、それぞれの棒の下に名前（Iris Xe／GTX 1650 Ti）が出る
   - 「設定」→「使用量」→「表示するGPU」で、「すべて」「自動（使用率の高い方を1行）」「どちらか1つだけ」を選べる
   - それぞれの行が、Task Managerの「GPU 0／GPU 1」と値が合うか
3. **RAMの併記**: 「RAMの量（GB）も表示」をオンにすると、「9.8 / 15.7 GB」のように出るか
4. **動作状態**: 「設定」→「動作状態」の欄に、いまの検知結果（電源、状態、手前のアプリ）が出ます
   - 電源ケーブルを抜く → 数秒で「バッテリー」になり、使用量の更新が2秒ごとになるか
   - バッテリー節約をオンにする（ケーブルをつないだまま） → 「節約中」と出て、バッテリー扱いになるか
   - 全画面のゲーム（または動画をF11や全画面ボタンで全画面に） → カードが薄くなり「停止中」になるか。抜けるとすぐ戻るか
   - 枠なし全画面のゲームで止まらないときは、ゲームを手前にしたあとガジェットの「直前のアプリを追加」を押して、ゲーム扱いに登録できるか
   - Win+Lでロックして戻る → 「停止中（ロック）」を経て、すぐ更新されるか（ロック中は窓が見えないので、戻った直後の表示で確認）
   - スリープから戻ったとき、すぐ値が更新されるか
5. 「通常／バッテリー／ゲーム中」のボタンは試験用の固定です。「自動（実測）」に戻すと実測に従います

## 試すこと（フェーズ2までの確認項目）

1. 窓が透明で出るか（カード以外は壁紙が見える）
2. 起動時は「擬似ガラス」です（壁紙をぼかして、カードの背景に敷く方式）。「なし／アクリル／ブラー／Mica」と見比べる
   - カードの背景が、後ろの壁紙のぼかしになっているか
   - 窓を動かしても、壁紙との位置が合ったままか（動かしている間は少し遅れることがあります）
   - 「設定」のぼかしの強さ・ガラスの濃さを変えると、見え方が変わるか
   - 壁紙を変えたときは、アプリを開き直すと反映されます
3. 各方式で、バーの「ここをドラッグして移動」をつかんで窓を動かし、重さを見る
4. 明るい壁紙と暗い壁紙の両方で見る
5. 「設定」を押すと、時計の切替・色・動作状態の試験が使える
6. 設定の「サイズと表示」で、全体・カードごとの大きさ、レーダーの高さ、カードの表示のオン・オフを変えられる。窓の大きさは、カードの合計に合わせて自動で変わる

## 教えてほしいこと（フェーズ3）

- ビルドが通ったか。エラーが出たときは、その全文
- 使用量のカードと、Task Managerを並べたスクリーンショット（CPU・GPU・RAM）
- 「表示するGPU」の一覧に出た名前
- 「動作状態」の欄の表示（通常時、ケーブルを抜いたとき、全画面のゲーム中）
- 止まらなかったゲームや、止まってほしくないのに止まった場面（例: 全画面の動画）
- 設定の「使用量の取得:」に黄色い文が出たときは、その全文
- Task Managerで見た、このアプリのCPUとメモリ（目標はCPU 1%未満、150MB以下）

```powershell
npm run build
```

## メモ

- Rustのコードは、Windows向けの型チェック（cargo check）とclippyを、警告なしで通してあります。ただし、Windowsの実機でのビルドと実行はまだです。エラーが出たら全文を共有してください。
- `src-tauri/Cargo.lock` を同梱しています。確認したときの部品の版（Tauri 2.12.5、windows 0.62.2）に固定するためです。
- 窓はいまは普通の窓です。デスクトップ表示（Win+D）でも残す処理は、フェーズ5で入れます。
- 全画面の動画（ブラウザの全画面など）も「ゲーム中」と判定され、更新が止まります。困る場合は「ゲーム中の動作」を「何もしない」にできます。
- 外付けGPU（GTX 1650 Ti）が休止しているときは、そのGPUは0%と表示します。
- アイコンは仮のものです。
