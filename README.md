# DesktopGadget（フェーズ5：常駐化）

見え方1（すりガラスのカード）を、Tauriの透明な窓に載せたデスクトップガジェットです。仕様書のフェーズ1〜5を、すべて実装しました。

- フェーズ1〜4: 擬似ガラス、時計、CPU・GPU・RAMの実測、動作状態（電源・ゲーム中・ロック）、天気・警報・雨雲レーダー
- **フェーズ5（今回）**: 常駐化
  - **Win+Dでも残す**: 窓の持ち主をデスクトップにし、最背面・非アクティブにした（「デスクトップに付ける」）。ドラッグやボタンの操作はそのままできる。万一隠されたときは、0.5秒以内に表示し直す
  - **トレイアイコン**: 左クリックで設定を開く。右クリックのメニューで、時計の切替、表示する／隠す、位置の固定、左上に戻す、終了
  - **設定画面を別の窓に**: ガジェットの「⚙ 設定」かトレイから開く。変更はすぐにガジェットに反映する
  - **設定をファイルに保存**: `%APPDATA%\local.desktopgadget\settings.json`。書き出し・読み込みもできる
  - **位置**: 動かした位置を覚え、次の起動で戻す。外付けモニターを外すなどして画面の外に出たら、メインの画面の左上に戻す。モニターや座標を指定して動かせる
  - **自動起動**: ログイン時に起動する（Windowsの「スタートアップ」に登録）
  - **壁紙の変更**: 30秒以内に気づいて、擬似ガラスを作り直す（開き直し不要に）
  - ガジェットの上のバー（移動のつまみと設定ボタン）は、マウスを乗せたときだけ出す。比較用だったぼかし方式のボタンは外した

## 追加カード：温度・ネットワーク

- **温度**: CPUとGPUの温度を、半円ゲージで横に並べて出す。目盛りは30〜100℃で、60℃と80℃で緑・黄・赤の範囲に分ける。直近1分で2℃以上上がった・下がったときは、数値の横に↑↓を出す。単位は「天気」の温度の単位（℃／℉）に従う（ゲージの目盛りは℃のまま）
  - CPU: Windowsの熱ゾーン（ACPI）の値。管理者権限なしで取れるのはこの値までで、CPU本体（パッケージ）の温度とはずれることがある。機種によっては出ない
  - GPU: Task Managerと同じ仕組み（D3DKMT）。使われているGPUだけ読み、休止中の外付けGPUは「休止中」と出す（読むことで起こして電池を減らさないため）。温度を返さないGPU（内蔵GPUに多い）は行を出さない
- **ネットワーク**: 受信・送信の速さと、直近60回分のグラフ。Wi-Fi・有線などの物理的なアダプターだけを合計する（仮想アダプターやVPNの二重計上を避ける）。単位は Mbps／MB/s を選べる
- どちらも使用量と同じ間隔で更新し、ゲーム中・ロック中は止まる。表示のオン・オフ、大きさ、受信・送信の色、文字の色は設定で変えられる
- 横2列のときは、左に時計・使用量・温度、右に天気・ネットワークを並べる
- 全体の大きさ50%なら、雨雲レーダーを出していても、すべてのカードが縦1列で約620pxに収まる（1920×1080・拡大率150%の画面で、窓に使える高さ約624px以内）。そのために、上のバー（移動・設定）はマウスを乗せたときだけカードの上に重ねて出し、カードの間隔も全体の大きさに合わせて縮むようにした
- 全体の大きさを変えると、カードの幅も同じ割合で縮むようにした（これまでは高さだけ縮み、幅は440pxのままだった）
- カードごとの大きさを変えても、カードの幅はそろう（いちばん大きいカードの幅に合わせ、ほかのカードは中身を並べる幅を広げる。中身の幅は440pxより狭くならないので、文字がはみ出さない）

### 試すこと（追加カード）

1. 温度のカードに「CPU」と「GPU」の半円ゲージが出るか。Task Managerの「パフォーマンス」→ GPU 1（GTX 1650 Ti）の温度と、GPUの値が合うか
   - ゲームなどで温度が上がると、ゲージが黄・赤の範囲に進み、数値の横に「↑」が出るか
1. 「全体の大きさ」を50%、「並べ方」を「自動」、雨雲レーダーをオンにして、すべてのカードが縦1列に並ぶか（横2列にならないか）
2. GTX 1650 Ti を使わない状態では「休止中」、ゲームなどで使うと温度が出るか
3. CPUの値が、極端におかしくないか（ずっと同じ値のまま、など。そういう機種もある）
4. 大きなファイルをダウンロードして、受信の数値とグラフが上がるか。Task Managerの「Wi-Fi」の受信と、おおむね合うか
5. Wi-Fiを切ると「つながっていません」になるか

## 準備（初回のみ）

1. **Microsoft C++ Build Tools** を入れる（インストーラーで「C++ によるデスクトップ開発」を選ぶ）
2. **Rust** を入れる（rustup。既定の MSVC 版でよい）
3. **Node.js**（LTS）を入れる
4. WebView2 は Windows 11 に標準で入っています

入れたあと、PowerShell を開き直してください。

## 起動

```powershell
cd desktop-gadget
npm install
npm run dev
```

初回はRustの部品を取得してビルドするため、数分かかります。

## 試すこと（フェーズ5）

1. **起動**: ガジェットがタスクバーに出ず、通知領域（右下）にアイコンが出るか
2. **Win+D**: Win+D（またはタスクバーの右端をクリック）でデスクトップを表示しても、ガジェットが残るか。もう一度Win+Dで元に戻したとき、ほかの窓の下にいるか
3. **最背面**: ガジェットをクリック・ドラッグしても、ほかの窓より前に出てこないか
4. **移動**: マウスを乗せると上に「⠿ ドラッグして移動」と「⚙ 設定」が出るか。つまみでドラッグできるか
   - 動かしてからアプリを終了し、もう一度起動すると、同じ位置に出るか
5. **トレイ**: アイコンの左クリックで設定画面が開くか。右クリックのメニューで、時計の切替、表示する／隠す、位置の固定、左上に戻す、終了がそれぞれ効くか
6. **設定画面**: ガジェットとは別の窓で開き、変更（時計、色、場所、レーダーなど）がすぐガジェットに出るか
   - 「位置を固定する」をオンにすると、移動のつまみが出なくなるか
   - 「表示するモニター」「位置」「左上に戻す」でガジェットが動くか
7. **外付けモニター**: ガジェットを外付けに移してからケーブルを抜くと、数秒でノートの画面の左上に戻るか
8. **設定のファイル**: 「書き出す…」で保存し、何か変えてから「読み込む…」で元に戻るか
9. **自動起動**: リリース版（`npm run build` でできる `desktop-gadget.exe`）を起動し、設定で「ログイン時に自動で起動」をオンにして、サインインし直すと出るか（目標: ログイン後5秒以内）
10. **壁紙**: 壁紙を変えて30秒ほど待つと、カードの背景（擬似ガラス）が新しい壁紙になるか
11. **置き方の切替**: 「デスクトップでの置き方」を「通常の窓（最背面）」にすると、Win+Dで隠れるようになるか（「デスクトップに付ける」が効かない環境のための逃げ道）

## 試すこと（フェーズ4）

1. **場所**: 「設定」→「天気」→「地名で探す」に地名（例: 千代田区、札幌）を入れて「検索」し、候補を選ぶ
   - カードに「地名・天気」「気温」「湿度」と「最終更新 HH:MM ／ 天気: Open-Meteo.com」が出るか
   - 設定の「場所：」の下に「警報の地域：○○」が出るか。違うときは「警報の地域」で選び直せる
   - 緯度・経度での指定も試す（例: 35.6812 / 139.7671）
2. **気温・湿度**: 天気予報サイトやスマホの天気と比べて、おおむね合うか（Open-Meteoは観測ではなく予報モデルの値なので、数度ずれることがある）
3. **温度の単位**: ℃／℉を切り替えると表示が変わるか
4. **警報・注意報**: 湿度の下に、発表中のものが重い順に2件まで出るか。ないときは「警報・注意報なし」
   - 気象庁の「警報・注意報」のページ（同じ市区町村）と内容が合うか
   - 札にマウスを重ねると、地域名と発表時刻が出る
   - 「警報の表示の試験」で、各段階の色と並びを確かめられる（実際の発表を見るときは「実際の発表（気象庁）」に戻す）
5. **雨雲レーダー**: 「雨雲レーダーを表示」をオンにする
   - 地図の上に雨雲が出て、左上の時刻が「実況」から「予測 +10分…+60分」へ進むか
   - 中心の白い輪が設定した場所か（気象庁の「雨雲の動き」と見比べて、雨雲の位置が合うか）
   - 「レーダーの範囲」（広域／標準／詳細）と「地図の色」（ダーク／ライト）を切り替えて、見やすいか
   - 雨が降っていない日は雨雲が出ません。そのときは「広域」にすると、どこかの雨が見えることがあります
6. **オフライン**: Wi-Fiを切って10〜20分おく → 「古いデータ（最終取得 HH:MM）」が出て、値は残るか。つなぎ直すと戻るか
7. **動作状態との連動**: ゲーム中は雨雲のアニメも止まり、終わるとすぐ天気を取り直すか

取得先の設定ファイルの場所は、「設定」→「天気」のいちばん下に出ます。気象庁のURLが変わったときは、このファイルを書き換えてアプリを開き直せば対応できます。

## 試すこと（フェーズ3）

起動して2秒ほど待つと、使用量の欄に実測の値が出ます（最初の1秒ほどは「—」）。

1. **CPU・RAM**: Task Manager（パフォーマンス タブ）と並べて、値がおおむね合うか
2. **GPU**: 何か重い処理（動画の再生、ゲーム、ブラウザのWebGLデモなど）をして、値が上がるか。既定では、GPUごとに1行ずつ並び、それぞれの棒の下に名前（Iris Xe／GTX 1650 Ti）が出る
   - 「設定」→「使用量」→「表示するGPU」で、「すべて」「自動（使用率の高い方を1行）」「どちらか1つだけ」を選べる
   - それぞれの行が、Task Managerの「GPU 0／GPU 1」と値が合うか
3. **RAMの併記**: 「RAMの量（GB）も表示」をオンにすると、「9.8 / 15.7 GB」のように出るか
4. **動作状態**: 「設定」→「動作状態」の欄に、いまの検知結果（電源、状態、手前のアプリ）が出ます
   - 電源ケーブルを抜く → 数秒で「バッテリー」になり、使用量の更新が2秒ごとになるか
   - バッテリー節約をオンにする（ケーブルをつないだまま） → 「節約中」と出て、バッテリー扱いになるか
   - 全画面のゲーム（または動画をF11や全画面ボタンで全画面に） → カードが薄くなり「停止中」になるか。抜けるとすぐ戻るか
   - 枠なし全画面のゲームで止まらないときは、ゲームを手前にしたあとガジェットの「直前のアプリを追加」を押して、ゲーム扱いに登録できるか
   - Win+Lでロックして戻る → 「停止中（ロック）」を経て、すぐ更新されるか（ロック中は窓が見えないので、戻った直後の表示で確認）
   - スリープから戻ったとき、すぐ値が更新されるか
5. 「通常／バッテリー／ゲーム中」のボタンは試験用の固定です。「自動（実測）」に戻すと実測に従います

## 試すこと（フェーズ2までの確認項目）

1. 窓が透明で出るか（カード以外は壁紙が見える）
2. 起動時は「擬似ガラス」です（壁紙をぼかして、カードの背景に敷く方式）。「なし／アクリル／ブラー／Mica」と見比べる
   - カードの背景が、後ろの壁紙のぼかしになっているか
   - 窓を動かしても、壁紙との位置が合ったままか（動かしている間は少し遅れることがあります）
   - 「設定」のぼかしの強さ・ガラスの濃さを変えると、見え方が変わるか
   - 壁紙を変えたときは、アプリを開き直すと反映されます
3. 各方式で、バーの「ここをドラッグして移動」をつかんで窓を動かし、重さを見る
4. 明るい壁紙と暗い壁紙の両方で見る
5. 「設定」を押すと、時計の切替・色・動作状態の試験が使える
6. 設定の「サイズと表示」で、全体・カードごとの大きさ、レーダーの高さ、カードの表示のオン・オフを変えられる。窓の大きさは、カードの合計に合わせて自動で変わる

## メモ

- Rustのコードは、Windows向けの型チェック（cargo check）とclippyを、警告なしで通してあります。ただし、Windowsの実機でのビルドと実行はまだです。エラーが出たら全文を共有してください。
- `src-tauri/Cargo.lock` を同梱しています。確認したときの部品の版（Tauri 2.12.5、windows 0.62.2）に固定するためです。
- Win+Dで残す方法は、仕様書で候補にしていた「デスクトップの層に埋め込む」（tauri-plugin-desktop-underlay）ではなく、「窓の持ち主をデスクトップにする」方法にしました。埋め込む方法では窓がマウス操作を受け付けなくなりますが、この方法ならドラッグや設定ボタンが使えます。Windowsの版によって効かない場合に備え、隠されたら表示し直す見張りも入れています。
- ガジェットの窓は、クリックしても前面に来ない（非アクティブの）窓です。そのため、文字の入力（地名検索など）は設定画面の窓で行います。
- アプリの終了は、トレイのメニューの「終了」から行います。
- 自動起動は、いま動いている実行ファイルを登録します。開発版（`npm run dev`）で登録すると開発版が起動するので、リリース版で登録してください。
- 全画面の動画（ブラウザの全画面など）も「ゲーム中」と判定され、更新が止まります。困る場合は「ゲーム中の動作」を「何もしない」にできます。
- 外付けGPU（GTX 1650 Ti）が休止しているときは、そのGPUは0%と表示します。
- 警報・注意報は、令和8年体系に合わせて4段階にしました（仕様書は3段階）。色は気象庁の段階の色にそろえ、特別警報（レベル5）は黒、危険警報（レベル4）は紫、警報（レベル3）は赤、注意報（レベル2）は黄です。名前も「レベル3大雨警報」のように、段階つきで出します。
- この警報の表示は、避難などの判断の唯一の根拠にしないでください。表示が遅れたり止まったりすることがあるため、気象庁の発表で確認してください。
- 気象庁のJSONとタイルは、公式に案内されたAPIではありません。形が変わると「取得できません」と表示されます（気温・湿度は続けて出ます）。
- レーダーの時刻一覧は、5分より短い間隔では取りに行きません（気象庁への負荷に配慮）。取得したタイルは、アプリの中にためて使い回します。
- 警報の地域を推定するために、地点の緯度・経度を国土地理院の逆ジオコーダーに送ります（場所を設定したときだけ）。そのほかの送信先は、Open-Meteo（地名・緯度経度）、気象庁、地理院タイルだけです。
- 予備のデータ元（RainViewer）は、まだ入れていません。気象庁のタイルが使えなくなったときに足します。
- アイコンは仮のものです。
