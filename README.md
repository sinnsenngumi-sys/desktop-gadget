# DesktopGadget

Windows のデスクトップに、すりガラス風のカードで「時計・天気・PCの状態」を常駐表示するアプリです。
Rust（Tauri 2）と Win32 API で、OS から値を直接取り、省電力と負荷の少なさを設計の中心に置いて作りました。

*A frosted-glass desktop widget for Windows 11, written in Rust (Tauri 2) with direct Win32 API access: system monitor (CPU/GPU/RAM, temperature, network), weather with Japan Meteorological Agency radar and warnings, and power-aware update scheduling.*

## できること

| カード | 内容 |
| --- | --- |
| 時計 | デジタル／アナログ、秒表示、日付 |
| 天気 | 気温・湿度・天気、今日の最高／最低、気象庁の警報・注意報、雨雲レーダー（過去2時間〜60分先のアニメ） |
| 使用量 | CPU・GPU（複数GPUを個別に）・RAM の使用率 |
| 温度 | CPU・GPU の温度（半円ゲージ、上昇・下降の矢印） |
| ネットワーク | 受信・送信の速さと、直近60回分のグラフ |

ほかに、次の機能があります。

- デスクトップの表示（Win+D）でも消えない常駐
- トレイアイコン、別の窓の設定画面
- 設定ファイル（JSON）への保存と、書き出し・読み込み
- 自動起動
- 二重起動の防止
- 壁紙の明るさに合わせた文字色の自動調整

## 技術的なポイント

組み込みソフトの開発で大事にされる「ハードウェアやOSに近い層を扱うこと」「限られた資源で動かすこと」「異常時にも止まらないこと」を意識して作りました。設計の判断を、検討した案と理由つきで [docs/design.md](docs/design.md) にまとめています。

### 1. OS の低レベルの API を直接扱う

使用量は、汎用ライブラリに頼らず、Windows の API から直接取っています。

| 取得するもの | 使った API | 工夫した点 |
| --- | --- | --- |
| CPU 使用率 | PDH（性能カウンター）`% Processor Utility` | Task Manager と同じ値になるカウンターを選んだ |
| GPU 使用率 | PDH `GPU Engine(*)` + DXGI | 処理エンジンごとにプロセス分を合計し、その最大値を使う（Task Manager と同じ定義）。アダプターは LUID で突き合わせ、内蔵・外付けの2枚を区別する |
| GPU 温度 | D3DKMT（`D3DKMTQueryAdapterInfo`） | 使用中の GPU だけを読む。休止中の外付け GPU を読みに行って起こし、電池を減らすことを避ける |
| CPU 温度 | PDH `Thermal Zone Information` | 管理者権限なしで取れる ACPI の熱ゾーンを使う（制約は下記） |
| ネットワーク | IP Helper（`GetIfTable2`） | 物理アダプターだけを合計し、フィルターや仮想アダプターによる二重計上を除く。カウンターが戻ったときにも、値が跳ねないようにする |
| 動作状態 | `GetSystemPowerStatus`、`SHQueryUserNotificationState`、前面窓の判定 | バッテリー・省電力モード・全画面（枠なしを含む）・ロックを検知する |

### 2. 限られた資源で動かす（省電力と負荷）

- **状態に応じた更新間隔**: 状態を「通常／バッテリー／ゲーム中／ロック中」に分け、更新の間隔を切り替えます。
  - バッテリー中は間隔を倍にし、ゲーム中とロック中はすべての更新を止めます。
  - 復帰したとき（スリープからの復帰も含む）は、すぐに1回更新します。
- **外部サービスへの負荷を抑える**:
  - 雨雲レーダーの時刻一覧は、5分より短い間隔では取りに行きません。
  - 取得したタイルはキャッシュして使い回します。上限を決め、古いものから捨てます。
  - 雨雲のアニメの各コマは、取得したときに一度だけ描いておき、再生中は貼り替えるだけにしています。
- **すりガラスの表現（擬似ガラス）**: OSのぼかし効果は使わず、壁紙を一度だけぼかして画像にし、窓の位置に合わせて各カードの背景に敷いています。窓を動かしても、ぼかし直しは起きません。

### 3. 異常があっても止まらない

- **見張りのスレッド**（0.5秒ごと）:
  - 窓が隠されたり最小化されたりしたら、表示し直します。
  - 外付けモニターを外して窓が画面の外に出たら、メイン画面に戻します。
  - 動かした位置は、動きが止まってから保存します。
- **通信が切れても止めない**: オフラインや取得の失敗では、最後の値を残して「古いデータ」と表示し、ほかの表示は続けます。
- **形式が変わっても止めない**: 気象庁のデータは、公式に案内された API ではありません。そこで、取得先を設定ファイル（`sources.json`）に切り出し、知らないコードが来ても表示を続けるようにしました。2026年5月の警報の体系変更（危険警報の新設）にも対応しています。
- **安全な通信と保存**:
  - 通信先は、許可リストに書いたホストだけに、https で接続します。
  - 設定ファイルは、一時ファイルに書いてから置き換えます。書き込み中に止まっても、壊れません。

### 4. 実機で測って決める

- **ぼかし方式**: OS のぼかし（アクリル／Mica／ブラー）を実機で比べました。その結果、どれも窓全体にしかかからず、カードの形にならないとわかったので、擬似ガラスを採用しました。
- **Win+D 対策**: 「デスクトップの層に埋め込む」方式は、窓がマウス操作を受け付けなくなります。そこで、「窓の持ち主をデスクトップにする」方式を選び、実機で確かめました。
- **使用率**: CPU・GPU の使用率を、Task Manager と並べて照合しました。

### 5. テストと検証

- **Rust の単体テスト**（16件）: 値の取り出しと集計のロジックを、OS から切り離して試しています。
  - GPU のインスタンス名の解析と集計
  - 熱ゾーンの単位の変換
  - ネットワーク速度の差分
  - 警報 JSON の解析
  - 地域コードの対応づけ
  - 設定ファイルの検証
- **画面の自動テスト**（Playwright）: Rust 側との通信を偽物に差し替え、表示と動きを試しています。
  - ガジェットと設定画面、2つの窓の同期
  - 大きさの組み合わせ72通りでの幅のそろい方と、はみ出しの有無
  - 文字色の自動判定
- **Windows 実機での確認項目**: [docs/testing.md](docs/testing.md) にまとめました。
- **CI**（GitHub Actions）: Windows で `cargo clippy -D warnings` と `cargo test` を、Linux で画面のテストを回します。

## 構成

```
┌──────────────── 画面（WebView2: HTML / CSS / JavaScript）────────────────┐
│ index.html  時計・使用量・温度・設定・擬似ガラス・文字色の自動               │
│ weather.js  天気・警報・雨雲レーダー（タイルの合成と色の塗り直し）            │
│ net.js      ネットワークのグラフ                                           │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ Tauri のコマンド呼び出し（IPC）
┌───────────────────────────────┴──────── 本体（Rust）─────────────────────┐
│ sysmon.rs    使用量・温度・ネットワーク（PDH / DXGI / D3DKMT / IP Helper）  │
│ sysstate.rs  電源・ゲーム中・ロックの検知                                  │
│ weather.rs   天気・警報・レーダーの取得（許可リスト、キャッシュ）            │
│ resident.rs  常駐化（デスクトップに付ける、見張り、設定ファイル、自動起動）    │
│ lib.rs       コマンドの登録、壁紙の読み込み                                │
└──────────────────────────────────────────────────────────────────────┘
```

コードはおよそ4,500行です（Rust 約2,500行、画面 約2,000行）。

## インストール

[Releases](../../releases) にあるインストーラー（`DesktopGadget_x.y.z_x64-setup.exe`）を実行します。管理者権限は要りません。

署名をしていないため、初回は「WindowsによってPCが保護されました」と表示されることがあります。「詳細情報」→「実行」で進めてください。

## ビルド

準備するもの:

- Microsoft C++ Build Tools（「C++ によるデスクトップ開発」）
- Rust（rustup、MSVC 版）
- Node.js（LTS）

```powershell
npm install
npm run dev      # 開発用に起動
npm run build    # インストーラーと exe を作る
```

できるもの:

- インストーラー: `src-tauri\target\release\bundle\nsis\DesktopGadget_x.y.z_x64-setup.exe`
- exe 単体: `src-tauri\target\release\desktop-gadget.exe`

```powershell
cd src-tauri; cargo test; cd ..     # Rust の単体テスト
npx playwright install chromium     # 初回だけ
npm run test:ui                     # 画面の自動テスト
```

## 開発の進め方

1. 最初に仕様書（[docs/spec.md](docs/spec.md)）を作り、要件、データ元の調査、未決事項を整理しました。
2. 開発を5つのフェーズに分け、各フェーズの終わりに Windows の実機で確認して、次に進みました。
   - フェーズ1〜2: 見た目の試作と、ぼかし方式の比較
   - フェーズ3: 使用量と動作状態
   - フェーズ4: 天気・警報・レーダー
   - フェーズ5: 常駐化
   - そのあと: 温度とネットワークのカード、文字色の自動、exe 化
3. 実装には AI（Claude Code）を使いました。自分が担当したのは次のところです。
   - 要件と優先順位の決定
   - 設計案からの選択
   - 実機での検証と、不具合・改善点の指摘
   - 見た目の調整

## 既知の制約

- **CPU 温度**: 管理者権限なしで取れる、ACPI の熱ゾーンの値です。CPU 本体（パッケージ）の温度とずれることがあり、機種によっては出ません。
- **気象庁のデータ**: 公式に案内された API ではないため、形式が予告なく変わることがあります。
- **警報の表示**: 遅れたり止まったりすることがあります。避難などの判断には、気象庁の発表を確認してください。
- **全画面の動画**: ゲーム中と同じ扱いになり、更新が止まります（設定で変えられます）。
- **対応OS**: Windows 専用です。

## データの出典と利用条件

| データ | 提供元 | 条件 |
| --- | --- | --- |
| 気温・湿度・天気・最高／最低・地名検索 | [Open-Meteo](https://open-meteo.com/) | CC BY 4.0。無料の API は非商用に限る |
| 警報・注意報、雨雲レーダー | [気象庁ホームページ](https://www.jma.go.jp/) | 出典の表示が必要。色を加工した旨を画面に表示している |
| 地図、市区町村の推定 | [国土地理院（地理院タイル、逆ジオコーダー）](https://maps.gsi.go.jp/development/ichiran.html) | 出典の表示が必要 |

このアプリは個人での利用を想定しています。配布や商用の利用では、各データの条件を確かめてください。
